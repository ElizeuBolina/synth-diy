Uma única nota na matriz

Exemplo: tecla G no BUS 3. A matriz inteira é só a repetição deste mesmo circuito para cada tecla.

Tecla solta: a entrada não recebe sinal
Raspberry Pi Placa do teclado Raspberry Pi GPIO OUT BUS 3 ──[330R]───────o tecla aberta o───|>|──── GPIO IN G │ │ diodo └──── sem contato ──────┘ Resultado: o GPIO IN G fica no estado de repouso pelo pull-up/pull-down. O software entende: "G do BUS 3 não está pressionado".
Tecla pressionada: BUS 3 aparece na entrada G
Raspberry Pi Placa do teclado Raspberry Pi GPIO OUT BUS 3 ──[330R]───────o──── tecla fechada ────o───|>|──── GPIO IN G │ │ diodo └──── agora tem caminho ┘ Resultado: quando o software ativa BUS 3, o GPIO IN G muda de estado. O software entende: "G do BUS 3 está pressionado".

Tradução para nota musical

O software não sabe que existe uma tecla física chamada "G". Ele só enxerga coordenadas:

BUS 3 ativo + entrada G ativa = tecla (BUS 3, G)

Depois o mapeamento converte isso para uma nota MIDI, por exemplo G3 ou G4, dependendo da nota base escolhida.

Por que precisa varrer?

Porque todas as teclas G compartilham o mesmo fio de nota G. Para saber qual G foi pressionado, a Raspberry testa um BUS por vez:

  1. Ativa BUS 1 e olha se G respondeu.
  2. Ativa BUS 2 e olha se G respondeu.
  3. Ativa BUS 3 e olha se G respondeu.
  4. Se G respondeu só no BUS 3, então é a tecla G daquela faixa.

O papel do diodo

O diodo deixa o sinal passar em um sentido só. Isso evita que, ao tocar acordes, uma tecla crie caminho falso por outra tecla e gere nota fantasma.
